# 00 Agent 入口｜用 EduMatch 完成高等教育—就业市场匹配度分析

> 本文件是**接力棒**，不是枷锁：它告诉下一个 Agent「东西在哪、怎么不踩坑、哪些能帮你」。
> 里面任何一条如果不好用，**改掉或删掉**；发现多余就删，发现不对就改。真正不可让的只有 §0.4 的红线。

## 0. 三分工（先读这一条，其余都从它推出来）

### 0.1 原始权威数据 —— **你自己读**

培养方案 PDF、就业报告正文、课程大纲、岗位 JD 全文、政策原文、HTML 页面、以及
`data/raw/pdf_text/**` 的正文缓存、`data/processed/jobs.json` 的岗位原文——
**你直接读，这是你的强项**。

不需要先把它们"规整"成机器能吃的格式再喂给你。机器抽不出来的东西（课程名隐含的能力、
JD 里的真实要求、报告里的限定条件），恰恰要由你读出来。

**两套数据各有优劣，必须交叉对照：**

| 来源 | 优势 | 局限 | 怎么用 |
| --- | --- | --- | --- |
| **原始材料**：`data/source/**`（原始 PDF / DOCX / HTML）、`data/source/归档文本缓存/**` | **最准确**——就是原文，含表格、限定语、上下文、脚注 | **不好检索**：要一份份打开；部分扫描件无文本层 | **定案**、复核、读隐含信息 |
| **抽取产物**：`data/raw/**`、`data/processed/**`（课程库、事实库、岗位库、政策库、正文缓存） | **好检索**：秒级定位、已归一、可批量统计 | **未必全**：抽取有漏抽、有错配（本项目就出现过"Python 供给=0"的漏抽） | **找线索、快速定位、批量统计** |

**标准动作：先用抽取产物定位线索 → 再用原始材料核对定案 → 冲突时以原始材料为准。**

> 读原始 PDF/DOCX 时：能调用你自带的 PDF/Office 工具就直接读；没有工具就走项目抽取器
> （`edumatch/ingest/pdf_reader.extract_pdf`、`docx_reader.read_docx_text`）转成文本再读。
> 不要因为"不好读"就跳过原始材料——那正是漏抽被发现的地方。

> 反例（本项目真实教训）：曾有报告因"Python 抽取供给=0"判定编程能力缺失；
> 而把 61 门课逐条读完后发现《高级语言综合》《计算机软件基础》《Ros编程》《科学计算及其应用》
> **明确承载编程能力**。结论因此从"基础要补"反转为"基础扎实、缺工程落地"。
> **机器抽到的值 ≠ 事实；原文才是事实。**

### 0.2 算法与工具 —— **只在需要"算得准、口径统一、可复现"时用**

适用场景就这几类：**数据采集、同类校判定、需求加权匹配、缺口排序、可重复性校验**。
它们给你一个**可核对的参照**，不是你的判断依据。

- 匹配度 / SkillFit / Primary TSI / 缺口榜：**参考值**，用于交叉验证与排序；
- 分数与你的判断冲突时，**以原始材料为准**，然后**内部消化**：报告里只出现校正后的结论，
  冲突本身**不要逐条摊在正文**（读者会因此怀疑全部数字）。口径偏差合并成**一条**说明，
  放在报告的「数据口径说明」里；
- 只有在需要"换个人跑一遍得到同样数字"时，才需要严格走引擎命令。

### 0.3 技能与提示词 —— **是给下一个 Agent 的接力棒**

本文件、`PROMPT.md`、`AGENTS.md`、`docs/**` 都是**交接材料**：让下一个 Agent 知道
数据在哪、工具怎么调、踩过哪些坑。它们不是操作手册式的枷锁——
**发现不适用的就跳过，发现过时的就改，发现多余的就删。** 保持这套材料精简比保持它"完整"更重要。

### 0.4 不可让的红线（只有这四条）

1. **不造数**：数字要么来自工具，要么来自你标注了来源 URL 与抓取日期的外部权威数据；
2. **不补位**：缺失就写"证据不足/未获取"，不用常识或相似专业顶上；
3. **推断要标注**：写成「**推断：**…（依据：课程 X、Y）」，与「**原文：**…」区分开；
4. **隐私与合规**：个人数据不外泄；只读官方免登录 `*.edu.cn`；域名必须先实测核实再采。

> 其余全部都是**建议**：怎么读、读多少、要不要用哪个算法，你按任务判断。

## 1. 开工顺序（建议，不是审批流程）

1. **问清需求**（§2）：尺度 + 对象 + 目标岗位 + 已有材料。用户说一句你就开跑，通常得不到他要的答案。
2. **按需读交接材料**：`AGENTS.md`（踩过的坑）、`docs/data_sources.md`（数据在哪、三种模式）、
   `docs/下一阶段_TSI多尺度多角色应用层.md`（三尺度定义）；需要时再翻 `skills/` 下对应分项。
   **用不上就跳过**——这些是参考资料，不是前置审批。
3. **取数 → 读原始材料 → 写结论 → 交付**（§3–§6）。

## 2. 多轮交互协议（一次问不全，就分几轮问）

### 2.0 三条原则

1. **一次只问 2–3 个问题，且尽量给选项/锚点**——让用户"选"而不是"凭空想"。
   微观尤其如此：学生往往答不出"你掌握哪些技能"，但答得出"这门课修没修"。
2. **不要等信息齐了才给结果**。先出「基于现有信息的初步结论」，同时说明
   **补齐哪一项会让哪条结论变实**。用户答不上来的项不阻塞。
3. **每轮结束做进度回显**（已知 / 仍缺 / 下一步问什么），跨轮之间**复述确认**，
   防止误解累积。用户说"用默认"就按默认跑，并在报告里写明假设。

### 2.1 通用会话流程（五轮）

| 轮 | 目标 | 你做什么 | 给用户看什么 |
| --- | --- | --- | --- |
| 0 开场 | 定身份与尺度 | 问：你是学生 / 教师或院系 / 政府或机构？要分析"谁 × 什么岗位"？ | 复述尺度与对象 |
| 1 定对象 | 补齐院校/专业/岗位/区域 | 缺什么问什么，一次 2–3 个 | "我将分析 …，对吗？" |
| 2 补细节 | 按尺度问专项（§2.2–2.4） | **给选项、给锚点、给默认** | 进度回显：已确认 / 仍缺 |
| 3 复述确认 | 防误解 | 把全部输入复述一遍，请用户确认或纠正 | 一张"我的理解"清单 |
| 4 出结论 | 先给初步结论 | 不必等齐；标出哪些结论会因缺数据打折扣 | 初版报告 + **可补数据清单** |
| 5 深挖 | 用户挑一条 | 按需重跑、补采或换尺度 | 单点深入或下一轮问题 |

> 尺度与对象的默认推断：学生→微观、教师/院系→中观、政府/机构→宏观；
> 院校默认本地已有材料的那一类；岗位默认该专业岗位语料里最集中的那一族。

### 2.1b 交付层级与追问（新增，详见 `skills/10_scoped_report/SKILL.md`）

- **第一版只交付用户选定的那一层**：宏观 / 中观 / 微观。报告与 HTML 都不得出现另外两层的
  读数与图表；微观文档里不要放宏观区域结论，反之亦然。
- 命令行：`--scope macro|meso|micro|all`（省略则按 query 推断，交互时请用户确认）。
- **第一版产出后必须主动追问**："是否需要更完整的三视角（宏观+中观+微观）报告与 HTML？"
  用户要，再生成 `--scope all` 版本；不要默认把三视角一起塞给用户。
- 单层级报告按 Finding → Evidence → Model → Action → Simulation 写全；
  三视角完整版走 `agent/report.py` 的 18 节渲染。
- **HTML 只走既有版式**：任意院校/专业用 Core 的正式入口
  `python -m reporting.render --result <result.json> --scope <…> --out <报告.html>`；
  标准演示场景用 `_build\collect_data.py` + `_build\build_page.py`。
  版式与构件在 `EduMatch/reporting/`（`theme.py` + `components.py`）；
  **允许你基于它们自行编写新的页面/脚本**（模板见 `reporting/templates/`），
  但**禁止另造一套 CSS/版式**；`agent.runner --html` 只是内部预览，不是交付物。

### 2.2 中观（教师/院系）要多轮确认什么

1. **对象**：院校、专业；如果该校本地有多个年份的培养方案，问清用哪一版（默认最新）。
2. **目标岗位**：没有就先给候选（§2.5）。也可问"你是想对标某个具体岗位，还是想看整个岗位大类"。
3. **同类校口径**：要不要同类校对照（默认要）；口径选**同城 / 同层次 / 全国**哪一种。
4. **回显示例**：
   > 我按这样分析：**北京工业大学 · 人工智能 · 2025 版培养方案 × 大模型算法工程师**，
   > 同类校用**同城同层次 3 所**做对照。对吗？要改哪一项？

### 2.3 宏观（政府/机构）要多轮确认什么

1. **范围**：区域（北京市 / 全国 / 某城市群）；年份。
2. **口径**：专业是"单个专业"还是"专业大类"；岗位是"具体岗位族"还是"大类"。
3. **数量口径**：问用户手里有没有**毕业生规模 / 岗位总量**；有就直接用，没有你去权威源查
   （见 §3.5），查不到就明说"该口径未获取，数量结论暂缺"。
4. **是否要模拟**：政策/招生规模变化下的缺口推演。

### 2.4 微观（学生）——引导式画像采集（重点）

学生通常低估或说不清自己。**不要开放题式地问"你会什么"**，按这五步走：

**第一步：从课程问起（最有效）**
把该校该专业的**真实课程表**读出来（读 `data/source` 的培养方案），让学生勾选：
该课是「修过 / 在修 / 没修」，修过的再给档位「优 / 良 / 中 / 及格」。
把课程表分批给（专业课 + 数学 + 实践各一批），一次问一批，别一次抛 60 门。

**第二步：从"做过的事"问起**（比问"会什么"容易得多）
课程设计、大作业、竞赛、科研、实习分别做过什么？做到什么程度？

**第三步：用行为锚点代替抽象自评**（不要问"Python 掌握程度 0–1"）

| 能力 | 让用户选最像的一项 |
| --- | --- |
| 编程 | ① 没写过 ② 改过别人代码 ③ 能独立写脚本处理数据 ④ 能独立完成一个完整程序/项目 |
| 机器学习 | ① 只学过理论 ② 跑通过教程 ③ 自己训练并调过参 ④ 独立做过端到端项目 |
| 工程部署 | ① 没接触 ② 本地跑过 ③ 部署过服务 ④ 做过推理优化或上线 |
| 数据处理 | ① 只会 Excel ② 会写 SQL 查询 ③ 能独立清洗与分析数据 ④ 搭建过数据流程 |

**第四步：要证据，不要自评**
作品链接、代码仓库、证书、实习做了什么、竞赛名次——**有证据的项权重高于自评**。

**第五步：三角校验 + 每轮回显**
- 自评 vs 课程成绩 vs 项目产出**不一致时追问**（"你说没写过 Python，但课程设计是用 Python 做的？"）；
- 每轮把已收集的画像列成清单回显给用户确认（"目前你的画像是：Python=能独立写脚本、机器学习=跑通过教程……对吗？"）。

> 隐私：个人数据只用于本次分析，不进共享语料，不写入公共产物。

### 2.5 岗位探索（用户不知道目标岗位时）

1. 先跑 `python -m agent.runner --list-occupations` 看本项目支持的岗位族；
2. 结合该专业的岗位语料，列出**该专业真实在招的岗位**（读 `data/processed/jobs.json` 的真实 JD）；
3. 给用户 3–5 个候选，说明各自要求与薪酬区间；
4. 用户选定后再进入正式分析，**不要替用户拍一个岗位就当结论**；
5. 微观场景下可反过来做：先看用户画像像哪类岗位，再让他确认。

### 2.6 追问原则

- 一次最多问 2–3 个问题；能合理默认的就默认，并在报告里写明假设；
- 用户答不上来的项**不阻塞**：先出「证据不足版结论 + 补数据清单」；
- 明确告诉用户：缺哪一项会让哪一类结论打折扣；
- **多轮不等于拖沓**：任何一轮结束都要有产出（初步结论 / 进度回显 / 一份候选清单），
  不做"只索取不给回馈"的连续提问。

## 3. 数据获取：三种模式 + 联网补齐

### 3.0b 供给为 0 之前先核对课程漏行（2026-10-05 新增）

### 3.0c 岗位名泛化 / 宏观区域池 / 分层文件（2026-10-05 新增）

### 3.0d 自动补采：每次调用都先采全（2026-10-05 新增）

**默认动作**：`python -m agent.runner … --auto-harvest`（交互式调用时自动开启）。
它按插件流程一次做全，而不是抓到一个教学计划就收手：

1. **目标**：点名院校 + 同类院校（`edumatch/peers.py`，可解释排序）；
2. **材料穷举**：`培养方案 / 专业介绍 / 课程大纲 / 年度报告 / 就业质量报告 / 教学质量报告`
   （`edumatch/auto_harvest.py::ALL_KINDS`，新增材料类型时应加进这里）；
3. **域名由你联网检索、由系统核验**：先搜到该校官网/承载页 URL，再交回核验——
   `python scripts\discover_school_domain.py --school "<校>" --candidate "<URL>"`
   （标准：官方教育域后缀 + HTTP 200 + 页面含校名；通过写入台账并可直接采集）。
   本地台账/`carrier_pages.json`/采集台账只作**交叉验证与加速**，不是唯一来源；
   **不要用没通过核验的域名去采**。
4. **重试**：某来源被 WAF 拦或结构变化 → 走插件文档的**入口 B（承载页直采）**再试一次；
5. **复核**：采完跑覆盖审计，仍缺的材料与原因写进报告的**自动补采台账**；
6. 采到后分析自动切 `--source-mode hybrid`，把收割件并入供给。

命令：`--auto-harvest [--auto-harvest-peer-max N] [--auto-harvest-kinds …]`；
单独采一遍用 `python scripts\auto_harvest.py --school <校> --major <专业>`。

1. **岗位名泛化**：`edumatch/occupation.py` 有同义词表与 `title_variants()`；
   「算法分析师」→ 数据分析族，「高级数据分析师」→「数据分析」。
   `match_scope` 保持 `position` / `position+description` 不变，
   泛化信息看 `generalized` / `matched_terms` / `expansion`，正文要照实写"已泛化到 …"。
   **禁止**因为原词零命中就下"检索不到"的结论。
2. **宏观 = 区域同类专业课程池（peer）**：宏观回答"区域能供给什么"，不能拿一所学校顶替；
   渲染器已按层区分（macro→peer、meso→target），正文要写明"来自多所院校"。
3. **分层交付只新增不覆盖**：
   `python -m reporting.render --result result.json --scope all --out-dir <目录> --prefix 报告`
   产出 `报告_macro/_meso/_micro/_all.html`；补做单层时再跑一次，**已有文件保留**。
4. **词表噪声**：渲染层已用 `edumatch/vocab.py` 过滤通用词（问题/场景/制定…）并合并
   "算法 / 算法分析"这类包含项；正文不要罗列这些无信息量的同类项。

培养方案解析会漏行；漏掉的语言课会让 Python/Java/C 的供给被记 0，看起来像"专业没教"。
出结论前对**点名院校 + 专业**跑一次：

```
python scripts\audit_course_coverage.py --school <院校> --major <专业> [--year <年份>]
```

它对比培养方案原表的「课程代码 + 课程名」与引擎课程库，并单独点名语言类漏行。
实测：北工大 2024 版信管原表 72 门、引擎库 69 门，缺 `Python语言(0009923)`、
`Java语言II(0003774)`、`C语言程序设计(0007159)`。**这类 0 必须写成
"课程表已列出但未入库（解析漏行）"，不能写成"专业没有该能力"。**

### 3.0 全面检索（默认动作，缺一不可）

任何"没查到"的结论，只有**穷举五个来源**之后才成立；次序固定、每条都要记录状态与原因：

| 顺序 | 来源 | 说明 |
| --- | --- | --- |
| ① | `data/raw/pdf_text/**` | 已抽取正文，最快 |
| ② | `data/source/<数据类型>/<院校>/**` | 规范一手材料；PDF 按需抽正文并缓存（`edumatch/pdf_text.py`） |
| ③ | `../AI竞赛数据归档/**` | 只读归档，常有更早年份报告 |
| ④ | `data/harvest/<院校>/**` | 插件离线回放产物 |
| ⑤ | `vendor/edu-material-harvest` | 联网采集（入口 A 全站/栏目、入口 B 承载页直采）；域名必须已核实 |

台账由 `edumatch/retrieval_sweep.py::sweep_sources` 生成（`result["retrieval_ledger"]`），
每条带 `hit / extracted_pdf / error / need_online / miss` 与原因；报告 §3 与单层级报告都会
把台账与"联网补采计划"一并列出。**校级报告里的"人才培养目标"是全校口径，只能作已披露的
代理、不计入 Primary TSI**；本专业目标必须来自专业名锚定的段落。详见
`skills/11_comprehensive_retrieval/SKILL.md`。

### 3.1 供给端模式

`--source-mode local` 只用 data/source 与本地库（离线、可复现，优先用）；
`--source-mode plugin` 只用 edu-material-harvest 联网采的目标院校（脱离本地库）；
`--source-mode hybrid` 本地全量 + 插件新采，合并去重（补采场景）。

### 3.2 插件采集（目标院校不在本地时）

**红线：联网采集只走项目自带插件，不要另起一套抓取。**
本项目的联网路径是 `vendor/edu-material-harvest`（`run_plugin_harvest` / MCP 12 工具）；
`urllib` / `curl` / 浏览器手工抓站**不属于**本系统路径，禁止用来替代它。
只有在确认插件路径不可用（插件缺失、目标站被 WAF 拦截、只有承载页 URL）时，
才按下面的"入口 B"直采，并在报告里写明用哪条路径、为什么插件直采不可用。

先核实域名（实测，不猜），再采集或预取同类校：

```
python scripts\resolve_school_domains.py --list peers --school 华中科技大学
python scripts\resolve_school_domains.py --school 武汉大学 --domain whu.edu.cn
python scripts\harvest_peers.py --school 北京工业大学 --major 人工智能 --max-peers 4 --list
python -m agent.runner --query "…" --source-mode hybrid --harvest --peers auto
```

**大站/被 WAF 挡时走承载页直采（入口 B）**：你联网搜到「挂着材料的那个页面」，再交给插件枚举：

```
python -m agent.runner --query "…" --source-mode hybrid --harvest --domain <校>.edu.cn --harvest-page "<承载页 URL>" --harvest-kind 培养方案
```

### 3.3 同类院校（中观建议做；没有就如实说明）

同类校按**全国高校名单**判定（层次/地域/校型，可解释排序，**不是排行榜**）：

```
python scripts\harvest_peers.py --school <目标校> --major <专业> --max-peers 4 --list
```

缺域名的候选会列成 `missing_domain`：**你负责联网找到官网并实测核实**（HTTP 200 且页面出现校名），
再写入台账。没有同类校数据时，报告里写明「同类对照不可用」，不要用全国平均去替。

### 3.4 HTML 材料页与原文（不要浪费已登记的链接）

插件对「纯 HTML 材料页」只登记链接（`html_links.json` / `candidates.md`）。**这些正文你可以直接读**：

  - 打开登记页面、抓正文，作为「专业介绍 / 课程大纲 / 培养方案」的原文；
  - 每条都记 `URL + 抓取日期`，并在报告里就地标注；
- 只读官方免登录 `*.edu.cn` 页面，遵守站点 robots 与访问频率要求。

### 3.5 宏观数量（毕业生总数、岗位总量）

本地数据没有连续的「毕业生人数 × 专业」口径，但**你可以联网从权威源取**：

1. 优先官方：教育部/统计局/地方人社局/高校信息公开网的年度报告；
2. 次选权威第三方（招聘平台年度报告、行业协会报告）；
3. **每个数字都要带来源 URL、口径说明、年份与抓取日期**；
4. 外部数据与算法计算的数字**分区呈现**，不得混算；
5. 取不到就写「未获取」，并说明会影响哪条结论——**不要用常识估一个数**。

## 4. 取数：直接读原始材料（不要造中间产物）

```
python -m agent.runner --query "分析<院校><专业>专业与<岗位>的匹配度" --occupation "<岗位>" --json data/processed/result.json --no-explain
```

`result.json` 里是你需要的一切，**逐项都带出处**：

- `courses`：该校该专业逐门课程（名称 / 学分 / 学时 / 必修 / **来源文件**）；
- `employment` 与 `evidence`：就业教学指标，每条含 `locator` / `quote` / `page` / `evidence_level`；
- `occupation`：目标岗位样本与要求分布（学历、薪资、职责）；
- `skill_gaps` / `occupation_match` / `primary_tsi`：**算法辅助指标，只作参考**；
- `retrieval`：本轮实际命中的材料清单（培养方案 N 份→课程 M 门、报告 X 份、政策 Y 份…）。

**需要细节就直接读原始数据**，不要去生成"证据包"之类的中间文件。两套都读，交叉核对：

**① 抽取产物（好检索，未必全）——先用来找线索**

- `data/processed/result.json`：本次分析的课程、事实、缺口、`evidence`、`retrieval`
- `data/processed/jobs.json`：岗位原文（公司 / 薪资 / 职责全文）
- `data/processed/pdf_facts.json`、`pdf_major_rows.json`：就业与教学事实（带页码）
- `data/raw/supplementary_courses.json`：课程库（学分/学时/必修）
- `data/raw/pdf_text/**`：1,779 份正文缓存（可直接检索原文）

**② 原始材料（最准确，不好检索）——再用来定案**

- `data/source/培养方案/<校>/*.pdf`、`data/source/课程大纲/<校>/**`、
  `data/source/年度报告/<校>/**`、`data/source/政策文件/**`、`data/source/专业介绍/<校>/**`
- `data/source/归档文本缓存/<sha1>.json`：归档 PDF 的逐页正文（事实复核用，`pdf_index.json` 里有映射）

用你自带的 PDF/Office 工具直接读；没有工具就用项目抽取器转文本
（`edumatch/ingest/pdf_reader.extract_pdf` / `docx_reader.read_docx_text`）。
**不要因为"不好读"就跳过原始材料**——漏抽就藏在这里。

> 判定规则：抽取产物与原始材料冲突时，**以原始材料为准**，并把校正结果写进报告
> （口径偏差合并成一条说明，见 §6.4）。

> `result["vocabulary"]` 里的候选缺口词是统计挖出的关键词，**不是技能**，只作线索；
> 是不是真技能由你判断，确认后写进 `data/skill_vocabularies/<专业>.json`
>（格式 `{"terms": [...], "note": "..."}`），下次分析自动采用。

> 注意：本节出现的路径与字段名是**给你读数据用的**，**不要写进报告正文**——
> 报告里只写中文结论与来源（怎么标见 §6.2/§6.3）。

## 5. 写结论：原始材料为主，算法为辅

### 5.0 分析次序（先做这一步，别先看分数）

1. **通读原始材料**：把这 61 门课（或 N 条 JD）**逐条读完**，在脑子里做两件事：
   - **课程 → 能力**：课程名蕴含什么能力？（例：《高级语言综合》《计算机软件基础》《机器人基础及Ros编程》
     → 编程与软件能力；《最优化》《离散数学》《概率论》→ 数学与建模基础；《自然语言处理基础实验》
     → 实验与工程实践）
   - **JD → 能力**：招聘方反复要的到底是什么？（不止关键词，还包括"负责…""熟悉…"里的真实要求）
2. **自己建立对应关系**：哪门课支撑哪项要求？哪项要求在整个课程体系里**确实找不到任何载体**？
3. **最后才看分数**：用匹配度/缺口榜**验证或质疑**你的判断。**分数与你的判断冲突时，以原始材料为准**，
   并在心里弄清冲突原因（多半是抽取口径有偏差，这是有价值的发现）——但**报告正文不写这些冲突**，
   只在「数据口径说明」里合并成一条；细节留在你自己的推理里或写进附录。

> 反面教材（本项目的真实教训）：曾有报告因"Python 抽取供给=0"判定编程能力缺失；而阅读全部课程后
> 发现《高级语言综合》《计算机软件基础》《Ros编程》《科学计算及其应用》**明确承载编程能力**。
> 结论因此从"基础能力要补"更正为"基础扎实、工程化落地环节缺"——**结论完全相反**。

### 5.1 中观（院校 + 专业 × 岗位）

1. **教了什么**：用真实课程表说清课程体系、学分结构、实践环节；
2. **市场要什么**：引用真实 JD（公司/岗位/薪资/职责原句），不要只给频次；
3. **差在哪**：把缺口落到**具体课程或环节**（哪门该加、哪门该加实践学时），并给出依据；
4. **和谁比**：同类校真实课程数/技能覆盖对照，说明为什么可比、对方数据可得性如何；
5. **数据边界**：哪些结论稳、哪些是「证据不足」，一次说清。

### 5.2 宏观（区域总量）

数量匹配（毕业生 vs 岗位）+ 技能结构匹配（课程池 vs 岗位语料）+ 岗位结构匹配，三者分开讲。
数量口径来自 §3.5 的外部权威源，标注来源与年份。
**读者是政府/机构**：语言同样按 §5.4 校准（无代号、无字段名），但重点放在"总量与结构、政策抓手"。

### 5.3 微观（个人 × 岗位）

用个人画像构建供给（课程/成绩/技能/项目/实习/证书），与目标岗位需求比对：
**优势 / 缺口 / 补齐路径（具体课程·项目·实习）**。个人结论只对本人，不做群体推断。
**读者是学生本人**：语言更要直白——少讲口径，多讲"你现在差什么、下一步做什么"。
画像采集**按 §2.4 的五步引导**（先勾课程 → 再问做过的事 → 行为锚点 → 要证据 → 三角校验），
不要用"你会什么？"这种开放题一次问完。

### 5.4 写给谁看：读者校准（最容易犯的错）

**中观报告的读者是专业负责人 / 院系 / 评估方，不是开发者。** 他心里只有三个问题：
*我现在什么样？差在哪？改什么、改了能好多少？* 写之前按这张表校准：

| 可以写进正文 | 只能放"附：来源与复现" |
| --- | --- |
| 中文能力名（技能适配度、缺口严重度、就业结果） | 指标代号（JOB1 / F2 / A3 / D7 …） |
| 校名、专业名、课程名、学分、学时 | 字段名（`occupation_match.match_100`、`supply_channels`） |
| JD 原句、报告原句、政策原句（带出处） | 文件名、JSON 路径、`run_id`、命令行 |
| 结论与依据、建议与预期效果 | 词表统计、覆盖率公式、维内权重 |

四条禁令：

1. **不出现指标代号**——一律换成中文名；确要保留编号，写在附录。
2. **不出现字段名/文件路径/命令/run_id**——全部下沉到最后一节。
3. **不出现"算法错了、假缺口、过匹配"这类内部冲突叙述**——你已按原文校正，正文只给校正后的结论；
   口径问题合并为**一条**说明，放在「数据口径说明」。
4. **不出现"辅助指标/非结论/不可断言"这类自我否定式表述**——它让读者不知道敢信什么。
   换成一句「**适用边界**」：把"哪些数据是校级口径、哪些是单时点"讲清楚即可。

> 检验方法：把报告给一位不了解本项目的老师读一遍。他若要问"F4 是什么""这个文件在哪"，
> 说明语言没过关；他若读完仍不知道**下周该做什么**，说明建议没过关。

## 6. 交付格式（默认中观版，读者 = 专业负责人；三端差异见 §6.5）

### 6.1 八节骨架与各节要求

| 节 | 写什么 | 硬要求 |
| --- | --- | --- |
| 1. 结论摘要 | 先写**分析对象 × 目标岗位**、匹配度构成（能力匹配 / 课程覆盖 / 岗位覆盖）、一句话结论；再 3–5 条要点，每条**一句结论 + 一句依据** | 纯中文，无指标代号、无字段名、无文件路径 |
| 2. 我们分析了什么 + 我的专业现状 | 开头一张**资料清单**（真实数字：几份培养方案、几份课程大纲、多少条岗位、几份报告、覆盖哪些年份）；然后课程体系、学分/实践结构、**近两版变化** | 数字必须真实，**小没关系，不许凑大数**；学分/学时给具体数 |
| 3. 市场要什么 | ≤5 条，**JD 原句**为主 | 每条原句标"来源：岗位 JD（公司/岗位名）" |
| 4. 差在哪 + 为什么差 | ≤3 条，每条落到**具体课程或环节**，并写清**缺口产生原因**（为什么没有载体 / 为什么覆盖不到 / 是新增要求还是本来就没有） | 写"哪门课没有载体"，不写"某技能分值为 0" |
| 5. 能力链路：专业 → 课程 → 技能 → 岗位 | 把链路画出来：**哪些课程支撑哪项岗位要求**；**哪些岗位要求没有课程支撑**（缺口）；哪些课程在岗位里没有对应需求 | 每条链路可追溯到课程名与 JD 原句；不要为了好看硬连 |
| 6. 怎么改 + 改了会怎样 | 每条建议：**做什么 / 挂靠哪门现有课 / 预期效果 / 依据** | 必须是读者能执行的动作；能量化就给 Δ（改课后的匹配度变化） |
| 7. 适用边界 | 一句话讲清哪些数据是什么口径 | 不写"不可断言清单"式免责 |
| 8. 附：来源与复现 | 指标编号、字段名、文件路径、命令、run_id、词表统计、覆盖率公式 | **所有工程细节只能出现在这一节** |

### 6.2 数字与来源怎么标

正文里的数字一律写成「**值（来源）**」，例子：

- …"模型部署"出现在 **30.7%** 的 AI 岗位里（来源：本地岗位库 16,161 条 AI 岗位，抓取 2026-07）
- …现行方案总学分 **162.5**、实践环节 **41 学分**（来源：北京工业大学 2025 版人工智能培养方案课程表）
- …校级落实率 **92.26%**（来源：北京工业大学 2023-2024 学年本科教学质量报告，校级口径）

外部联网数据必须给 `URL + 抓取日期 + 口径说明`。

### 6.3 正文禁用清单（出现即不合格）

- 指标代号：`JOB1 / F2 / F4 / A3 / B6 / C1 / D7 / M3 / S2 …`
- 字段名与路径：`occupation_match.match_100`、`supply_channels`、`data/processed/result.json`
- 命令与运行标识：`python -m agent.runner …`、`run_id`、`--json`、脚本路径
- 内部冲突叙述：「算法错了」「假缺口」「过匹配」「分数与原文冲突」逐条列举
- 自我否定式表述：「辅助指标」「非结论」「不可断言事项」
- 过程叙述：「读完入口协议要求的全部原始材料…并跑了引擎」

### 6.4 必须做到

1. **矛盾先解决再写**：若两处信息互相冲突（如"课程池来自 2025 版"与"2025 版的课没进池"），
   先查清是文件归属错、还是解析漏；**查不清就删掉拿不准的那一句**，绝不两说并存。
2. **口径偏差只写一条**：合并成一句放在第 2 节末尾，例如
   *"课程能力由课程名匹配得到，存在漏抽与泛化命中；本报告已按课程表与 JD 原文校正，
   引擎数值仅作参照。"*
3. **不给数据的部分不占篇幅**：同类校没采到就一句话说完（"需补采 N 所，本报告不做对比"）。
4. **建议落到课与环节**：不写"应加强工程化"，要写"增设《模型部署与推理优化》2 学分，
   可挂靠《大模型技术及应用综合实践》扩展 16 学时"。
5. **资料清单只写真数字**：写"分析了 1 份培养方案、42 份课程大纲、16,161 条岗位"，
   不写"分析了上千份资料"。**真实的小数字 + 可点击来源，比虚拟的大数字可信得多。**
6. **第 5 节「能力链路」是可信度的核心**：读者正是靠它判断"你是真读了材料，还是套了模板"。
   宁可只画 8 条有把握的链路，也不要铺满一屏牵强的连线。

### 6.5 三端（三尺度）的呈现重点不同

| 读者 | 报告重心 | 不要写成 |
| --- | --- | --- |
| 学生（微观） | 我差什么、下一步做什么、补齐路径 | 大段政策与区域数据 |
| 教师/院系（中观） | 课程体系缺什么、改哪门课、改了能好多少 | 个人隐私、区域总量 |
| 政府/机构（宏观） | 总量与结构、专业布局、政策抓手 | 单门课程的细节 |

同一份分析可以同时给三方用，但**交付时按读者裁剪**：给他要的那部分，其余一句话带过。

## 7. 可复现性（只在这件事上需要"严格"）

平时你按 §0 的分工自由发挥即可；**只有当"换个人/换一次跑要得到同样数字"时**，才需要：

- 走引擎命令并记录 `run_id`：同数据同模式，引擎是确定性的（`tests` 有可重复性断言）；
  你的措辞可以不同，但引用的**数字与缺口排序应一致**；
- `--source-mode local` 是离线复现的首选；
- 联网采集/外部取数随时间变化，记录抓取日期并说明"时点不同会导致差异"；
- 不修改 `data/source` 原始材料；新采数据落到规定位置并留台账。

## 8. 交付前自检

**内容红线（§0.4）**

1. 不造数：数字要么来自工具，要么来自你标注了来源 URL 与抓取日期的外部权威数据；
2. 不补位：缺失就写「证据不足 / 未获取」，不用常识或相似专业顶上；
3. 推断要标注：「**推断：**…（依据：课程 X、Y）」与「**原文：**…」分开写；
4. 隐私与合规：个人数据不外泄；只读官方免登录 `*.edu.cn`；域名先实测核实再采；
5. 插件采到「不像材料」的东西（如培养方案却是 .doc 表格模版）如实报告并隔离；
6. 政策只作背景关联，不做因果断言；同类校是**可解释对照**，不是排行榜，不发布名次。
