# 版式资产：给大模型"自己写页面"用

## 0. 先看零数据模板（每次生成前必看）

| 文件 | 说明 |
| --- | --- |
| `page_template.html` | **三视角模板**：完整结构 + 全部维度，**零真实数据**（数值为 null/未获取，文本为占位） |
| `page_template_micro.html` | 微观单层级模板（同样零真实数据） |
| `placeholder_result.json` | 模板背后的占位结果（schema 参考） |
| `build_page_template.py` | 重新生成模板：`python reporting/templates/build_page_template.py` |

模板与 `EduMatch-演示页面/index.html` **逐块对齐**：

| 区块 | 模板里有什么 |
| --- | --- |
| 封面 | **三入口门卡**（政府/教师/学生）：各自打分（Primary TSI / 目标岗位适配 / 个人适配）+ 子指标行 + **点击跳转**到对应层级 |
| 总览（`#overview`） | 三尺度**阶梯**（可点，带规模与口径）+「怎么读这张图」（A–E 证据等级图例）+ **三视图对照表**（同一技能在宏观/中观/微观供给与岗位需求） |
| 宏观 | 目标岗位画像、**需求侧画像（学历结构 / 行业分布 / 技能热度 / 薪资，多条形图）**、**宏观信息源 · 覆盖院校台账（逐校：角色 / 可核查课程 / 材料类型·状态 / 就业结果 / 来源渠道）**、**各校课程贡献条图**、**目标校×同类校×市场三角对照 + 技能级三方对照**、**同类高校就业结果对比（逐校条形）**、**政策与产业方向**、供需双条、四维雷达、16 项指标、TSI Tree、S1 与覆盖披露、全面检索台账、缺口表 |
| 中观 | 课程与岗位匹配（子指标）、**培养方案解剖（课程 × 技能矩阵，逐门可核查 + 未映射课程清单）**、**同类院校基准（逐技能本校 vs 同类校 vs 市场）**、缺口明细、证据冲突消解 |
| 微观 | L0–L4 证据分层（含口径说明）、**个人缺口条形图（需求 vs 个人供给）**、**四层缺口全量明细（汇总表 + 按层展开：项目名 / 需求 / 个人供给 / 缺口；证据不足按需求强度列前 12）**、优先行动（量化的单列，证据不足的按层归并） |
| 顶栏 | **单行、简短**（CSS 锁 `white-space:nowrap` + 省略号，不允许换行把顶栏顶高）：宏观＝`区域 · N 所高校`；中观＝`院校 · 专业`；微观＝`证据分层 L<n>`；其余为 `入口 / 阶梯与对照 / 数据与复现`。**已删掉** `院校 · 专业 · 岗位 · scope=…` 上下文小字 |
| 子页大标题 | 按当次分析生成：宏观＝`<专业>相关培养能力 · 覆盖 N 所院校 · M 门课程池 × <岗位> 可观察岗位招聘记录 K 条`；中观＝`<院校> · <专业> 培养方案 · T 门可核查课程 × <岗位> 能力要求`；微观＝`个人证据画像（L<n>）→ <岗位> 补齐建议` |
| 来源与复现 | **数据资产总览**（文档 / 课程 / 政策规模 + 采集入库量 + 证据等级分布）、**编号来源清单 [n]** + 正文上标**交叉引用**（可点进、可回跳「↑ 回到引用处」）+ run_id + 复现命令 + **自动补采台账（入口 / 本地已有 / 采到材料）** |
| 薪资 | 目标岗位月薪中位 / P25 / P75 + **月薪分档分布条图**；日薪与兼职岗位剔除并单独计数 |

Agent 生成正式报告时：先用 `reporting.render` 产出，再按模板逐项核对**有没有漏掉维度**；
缺数据的维度要显示「未获取」，**不能删掉**，也不能拿模板里的占位当数据。
这一步**必须逐页看最终报告**——不要用字符串检索脚本代替（脚本只能证明某段文字出现过，
证明不了数据真的用全了、维度真的都有读数）。

正式交付的两条路：

1. **直接用 Core 渲染器**（推荐，零维护）：

   ```
   python -m reporting.render --result <result.json> --scope all --out 三视角报告.html
   ```

2. **大模型自行编写渲染脚本 / 页面**（允许，且鼓励按需定制）：
   复用本目录同一套主题与构件，**不要另造 CSS**。

## 可复用的资产

| 资产 | 位置 | 用途 |
| --- | --- | --- |
| 主题 CSS/JS | `reporting/theme.py` 的 `CSS` / `JS` | 页面配色、字体、栅格、导航与路由脚本 |
| 版式构件 | `reporting/components.py` | `e / f2 / pct / comma / gap_bar / dual_bar / radar_svg / hbar / stat_card / indicator_grid / tsi_tree_html / alignment_html / retrieval_ledger_html / nav_html` |
| 完整示例 | `reporting/render.py` | 三视角与单层级页面的标准组装方式 |
| 自定义模板 | `reporting/templates/custom_report_example.py` | 只保留外壳、由你填充新章节 |

## 允许的自定义（示例）

- 新增章节：把 Finding / Evidence / Model / Action / Simulation 拆成更细的卡片；
- 新增图表：用 `radar_svg`、`gap_bar`、`hbar` 组合出新视图；
- 换数据源：把 `result.json` 换成别的结构化结果，只要沿用 `theme` + `components`。

## 不允许

- 另写一套 CSS / 版式（会出现"两个 EduMatch"）；
- 绕过引擎与证据链自撰结论（证据不足要写进报告，而不是替换掉引擎链路）；
- 把未标注来源的联网内容写进正文（联网只走 `vendor/edu-material-harvest` 插件，
  域名须先实测核实）。
